# Contributing

Useful contributions demonstrate a concrete improvement in investor review behavior.

1. Identify the affected skill and a realistic user request.
2. Provide the minimum synthetic or redacted inputs needed to reproduce the problem.
3. Describe the observed behavior and its business consequence. Include model, tools and file visibility when known.
4. Propose a focused change that preserves the user's scope and uses evidence appropriate to the company.
5. Exercise the changed behavior, then run the release builder and validator.

Do not add universal Seed/Series A round brackets, ARR floors or hard-coded benchmark hurdles without a justified user context. A passing synthetic test does not establish broad investment accuracy.

The company-calibration and raise-calibration references are intentionally bundled in each skill so independent installation works. Update all twelve copies together when changing their common behavior.

When a substantive skill changes, include a behavioral example and disclose exactly what was executed. Do not relabel same-context simulation as a blind or separate-provider evaluation. Avoid tests that only check whether a preferred phrase appears.

Keep all relative resource links within the individual skill folder. Use research links as starting points; inspect current primary sources when making time-sensitive claims. Preserve source acknowledgment for adapted ideas.

Public issues and pull requests must not include credentials, private founder/customer records or unreleased data-room materials. Fictional fixtures are preferred for reproducible tests.
